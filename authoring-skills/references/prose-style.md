# スキルの文章の書き方

このファイルは、スキルの文の組み立て方と言葉の選び方の規則です。
規則は unslop をもとに、日本語の文章に合わせて書き直しています。
本文を書くときと、書き終えて読み直すときに使います。

## 文の組み立て

### 1文には1つのことだけを書く

読み返さないと意味が取れない文は、2つの文に分けるか、節を削ります。

### 主語を書く

受け身の文では、誰が何をするのかが分かりません。
動作をする人やプログラムを主語にします。
主語が分からない場合や、主語に意味がない場合に限り、受け身で書きます。

```text
悪い例: ファイルが読み込まれ、フィールドが検証されます。
良い例: スクリプトがファイルを読み込み、フィールドを検証します。
```

### 記号で文を縮めない

矢印、記号、体言止めで文を縮めると、読み手が意味を補う必要があります。
助詞と動詞を補って、文として書きます。

```text
悪い例: 日付が不正 → exit 2、書き込みなし
良い例: 日付が不正な場合、スクリプトは終了コード 2 で終了し、ファイルに何も書き込みません。
```

### 同じものは同じ言葉で呼ぶ

「フィールド」「項目」「欄」のように言い換えると、読み手は別のものだと考えます。
1つの言葉を選び、ファイル全体でその言葉を使います。

### 太字と括弧を重ねない

太字は、段落の中で特に目立たせたい語に限ります。
括弧の中に補足を入れる代わりに、別の文を書きます。

### 文体を揃える

1つのファイルの中で、「です・ます」と「だ・である」を混ぜません。

### 大文字の命令より理由を書く

`ALWAYS` や `MUST` を大文字で書く代わりに、理由を1文添えます。
理由が書いてあれば、Claude は例にない場面でも判断できます。

## AI 特有の言い回し

### 中身のない形容語を使わない

次の語は、AI が書いた文章によく現れます。
多くの場合、具体的な情報を何も足していません。
削っても意味が変わらないなら削り、意味が変わるなら具体的な事実に置き換えます。

- 重要な、不可欠な、鍵となる
- さまざまな、多様な、多岐にわたる、豊富な
- 包括的な、シームレスな、堅牢な、柔軟な、革新的な
- 〜を実現する、〜を促進する、〜に寄与する、〜を強化する
- 〜の可能性を広げる、新たな価値を生み出す

```text
悪い例: さまざまなファイル形式に柔軟に対応する、包括的なスキルです。
良い例: PDF、DOCX、XLSX のファイルからテキストを抽出します。
```

### 「です」を飾って言い換えない

「〜として機能します」「〜の役割を担います」「〜を備えています」は、
たいてい「〜です」「〜があります」で足ります。

```text
悪い例: SKILL.md は、スキル全体の入り口としての役割を担っています。
良い例: Claude は最初に SKILL.md を読みます。
```

### 「X だけでなく Y」で前置きしない

「単なる X ではなく Y です」「X だけでなく Y も」と書く代わりに、Y を直接書きます。

```text
悪い例: このスクリプトは、単なるチェックツールではなく、品質を高めるパートナーです。
良い例: このスクリプトは、仕様違反とスタイルの逸脱を行番号付きで報告します。
```

### 無理に3つ並べない

項目を3つ揃えると文の調子は整いますが、3つ目が水増しになりがちです。
実際にある数だけ並べます。

### 意味のない範囲を書かない

「初心者から上級者まで」「小規模から大規模まで」は、両端の間に意味のある尺度がありません。
対象を直接書きます。

```text
悪い例: 小さなスクリプトから大規模なアプリケーションまで、幅広く使えます。
良い例: Python と TypeScript のプロジェクトで使えます。
```

### 比喩の名詞と気取った表現を使わない

「土台」「基盤」「エコシステム」「北極星」「両輪」「橋渡し」「羅針盤」のような比喩は、
技術的な言葉に見えても、たいてい具体的な言葉で言い換えられます。
「〜の扉を開く」「〜が息づく」のような飾った動詞も、そのまま意味を書きます。

```text
悪い例: 参照ファイルは、スキルの知識の土台です。
良い例: 参照ファイルには、テーブル定義と集計の規則があります。
```

### 印象ではなく、動作か数値を書く

「直感的に使える」「快適に書ける」は、読み手の感じ方を述べているだけです。
何が起きるのか、何ができるのか、どれくらいなのかを書きます。
同じ文が別のスキルにもそのまま書けるなら、その文はこのスキルについて何も述べていません。

```text
悪い例: 直感的なワークフローで、快適にスキルを作成できます。
良い例: 5つのステップを順に進め、最後にチェックリストと照らし合わせて読み直します。
```

## 水増し

### 前置きの言葉を削る

次の言い方は、削るか短い形に直しても意味が変わりません。

- 「〜することが重要です」「〜という点に注意が必要です」は、規則そのものを書きます。
- 「〜することができます」は「〜できます」と書きます。
- 「〜を行います」は、「検証を行います」を「検証します」とするように動詞で書きます。
- 「〜に関しては」「〜という形で」「基本的に」は削ります。

```text
悪い例: 基本的に、description に関しては三人称で書くことが重要です。
良い例: description は三人称で書きます。
```

### 予防線を重ねない

「〜という可能性も考えられるかもしれません」のように、ぼかす言葉を重ねません。
不確かな場合は「〜ことがあります」と1回だけ書きます。

```text
悪い例: 場合によっては、Claude がファイルを読まない可能性もあるかもしれません。
良い例: Claude は、リンクを2段たどるとファイルの一部しか読まないことがあります。
```

### ありきたりな締めの文を書かない

「これにより、より良いスキルが作成できます」「今後の活用が期待されます」のような
締めの文は削ります。
書くことがある場合は、次に何をするかを具体的に書きます。

### 副詞に頼らない

「非常に」「とても」「大幅に」「しっかり」「適切に」は、数値か具体的な動詞に置き換えます。
副詞で動詞を補っている場合は、動詞の選び方が合っていません。

```text
悪い例: タイムアウトを適切に設定し、処理を大幅に高速化します。
良い例: タイムアウトを30秒にします。処理時間は12秒から3秒になります。
```

### 平易な言葉を選ぶ

難しい言葉を使っても、たいてい意味は明確になりません。

- 「活用する」「利用する」は「使う」と書きます。
- 「実施する」は「する」と書きます。
- 「把握する」は「知る」か「確かめる」と書きます。
- 「担保する」は、何をどう確かめるのかを書きます。
- 「〜の観点から」は、何を基準にするのかを書きます。

## 読み直しのチェックリスト

書き終えたら、次の項目を1つずつ確かめます。

- [ ] 読み返さないと意味が取れない文がない。
- [ ] 受け身の文に、主語を書ける箇所が残っていない。
- [ ] 矢印や記号で縮めた文がない。
- [ ] 同じものを別の言葉で呼んでいない。
- [ ] 「重要な」「さまざまな」「包括的な」のような、中身のない形容語がない。
- [ ] 「〜の役割を担います」のような、「です」の飾った言い換えがない。
- [ ] 「X だけでなく Y」「X から Y まで」の形の文が、具体的な内容に直してある。
- [ ] 比喩の名詞や、印象だけを述べる文がない。
- [ ] 「〜することが重要です」「〜することができます」のような前置きがない。
- [ ] 予防線が重なっていない。
- [ ] 締めの文が、次にすることを具体的に書いているか、削ってある。
- [ ] 「非常に」「適切に」のような副詞が、数値か具体的な動詞に置き換えてある。
- [ ] 「活用する」「実施する」のような難しい言葉が、平易な言葉に置き換えてある。
