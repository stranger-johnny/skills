# スタイルガイドに沿ったスキル作成

このスキルは、Agent Skill を書くときとレビューするときの手順です。
内容と構成は Anthropic のベストプラクティスで決めます。
書式は Google の Markdown スタイルガイドに揃えます。
文章は unslop をもとにした規則で、AI 特有の言い回しと水増しを削ります。

## 3つの基準

内容と構成は Anthropic のベストプラクティスに従います。
description の書き方、自由度の決め方、ファイルの分け方がここに含まれます。
詳しい規則は [Anthropic のベストプラクティス](references/anthropic-best-practices.md)
にあります。

書式は Google の Markdown スタイルガイドに従います。
見出し、行の長さ、リスト、コード、リンクの書き方がここに含まれます。
詳しい規則は [マークダウンスタイル](references/markdown-style.md) にあります。

文章は unslop をもとにした規則に従います。
文の組み立て、AI 特有の言い回し、水増しの削り方がここに含まれます。
詳しい規則は [文章の書き方](references/prose-style.md) にあります。

Anthropic と Google のガイドが食い違う箇所は、マークダウンスタイルの「スキル向けの調整」に従います。
`[TOC]`、`<details>`、太字の擬似見出しをどう扱うかは、そこで決めてあります。

## ワークフロー

次のチェックリストをコピーして、終わった項目に印を付けてください。
既存のスキルのレビューだけを頼まれた場合は、Step 5 から始めます。

```text
- [ ] Step 1: 目的と使われる場面を確かめる
- [ ] Step 2: ファイル構成を決める
- [ ] Step 3: フロントマターを書く
- [ ] Step 4: 本文を書く
- [ ] Step 5: ソースを読み直して直す
```

### Step 1: 目的と使われる場面を確かめる

書き始める前に、次の4点を確かめます。
会話の中に答えがあればそこから拾い、足りない点だけをユーザーに尋ねます。

1. スキルで Claude が何をできるようになるか。
1. ユーザーがどんな言葉で依頼したときに、Claude がこのスキルを使うべきか。
1. 出力がファイル、文章、コマンドの実行のどれか。
1. 手順をどこまで厳密に決めるか。

ユーザーが実際に使った言葉は、Step 3 で description に入れます。

### Step 2: ファイル構成を決める

SKILL.md だけで足りるなら、ファイルを増やしません。
増やす場合は、次のディレクトリに分けます。

- `references/` には、Claude が必要なときだけ読む資料を置きます。
- `scripts/` には、毎回同じ結果が必要な処理を置きます。
- `assets/` には、出力に使うテンプレートやファイルを置きます。

決まった処理をスクリプトにすると、Claude が毎回コードを書く必要がなくなります。
結果が安定し、トークンも減ります。

参照ファイルは、すべて SKILL.md から直接リンクします。
参照ファイルから別の参照ファイルへのリンクは作りません。
Claude はリンクを2段たどると、ファイルの一部しか読まないことがあるからです。
ファイル名には内容を表す言葉を使い、パスはスラッシュで区切ります。

### Step 3: フロントマターを書く

`name` は64文字以内で、小文字、数字、ハイフンだけを使います。
`anthropic` と `claude` は含めません。
`processing-pdfs` のような動名詞形を第一候補にし、ディレクトリ名と同じにします。

`description` は1,024文字以内で書きます。
Claude はこの文だけを読んで、スキルを使うかどうかを決めます。
本文は、スキルを使うと決めた後にしか読みません。
そのため、次の内容をすべて description に書きます。

- スキルが何をするかを、三人称で書きます。
- 「Use when ...」に続けて、ユーザーが依頼に使う言葉を並べます。
- ユーザーが日本語で依頼するなら、日本語の言葉も入れます。

Claude は、使えるスキルがあっても使わずに済ませることがあります。
そのため、使う場面は少し広めに書きます。

### Step 4: 本文を書く

新しいスキルは、[スキルのテンプレート](assets/skill-template.md) をコピーして始めます。
`TODO` はすべて埋めるか、削除します。

内容は次のように書きます。

- Claude がまだ知らない情報だけを書きます。一般的な知識の説明は削ります。
- 規則には理由を1文添えます。理由があれば、Claude は例にない場面でも判断できます。
- 1つの概念には1つの用語を使います。
- 方法を1つ決めて書きます。代わりの方法は、それが必要な場合に限って書きます。
- 説明だけで済ませず、具体的な入力と出力の例を載せます。
- 日付で手順を分けません。古い方法は `## 古いパターン` という見出しの下に書きます。

書式は次のように書きます。

- H1 は1つだけにし、その直後に1〜3文の導入を書きます。残りの見出しは H2 から始めます。
- 見出しは `##` の形で書き、前後に空行を入れ、ファイルの中で重複させません。
- ワークフローの各ステップは、太字の行ではなく見出しにします。
- 本文は80文字で折り返します。日本語は句読点の直後で改行します。
- ネストしたリストは4スペースで字下げします。長い番号付きリストは、すべて `1.` で書きます。
- コードブロックには言語を書きます。言語がない場合は `text` と書きます。
- リンクテキストには行き先の名前を書きます。「こちら」や「ここ」は使いません。
- HTML は使いません。`<file>` のようなプレースホルダーはバッククォートで囲みます。
- 100行を超える参照ファイルには、冒頭に `## 目次` を置きます。
- 太字は、段落の中で特に目立たせたい語に限ります。

文章は次のように書きます。
規則の全体と良い例、悪い例は [文章の書き方](references/prose-style.md) にあります。

- 1文には1つのことだけを書き、主語を書きます。
- 「重要な」「さまざまな」「包括的な」のような、中身のない形容語を使いません。
- 「〜として機能します」「〜の役割を担います」は、「〜です」「〜があります」と書きます。
- 「X だけでなく Y」「X から Y まで」と書かず、Y や対象を直接書きます。
- 比喩や印象を述べる文ではなく、動作、値、ファイル名を書きます。
- 「〜することが重要です」「〜することができます」のような前置きを削ります。
- 「非常に」「適切に」のような副詞は、数値か具体的な動詞に置き換えます。
- 「活用する」「実施する」は、「使う」「する」と書きます。

### Step 5: ソースを読み直して直す

書き終えたら、マークダウンのソースを上から読み、次のチェックリストと照らし合わせます。
問題が見つかったら直し、もう一度チェックリストを確かめます。
すべての項目を満たすまで、これを繰り返します。

-   **内容と構成。** [Anthropic のベストプラクティス](references/anthropic-best-practices.md)
    の「公開前のチェックリスト」で確かめます。
-   **文章。** [文章の書き方](references/prose-style.md) の「読み直しのチェックリスト」で
    確かめます。
    AI 特有の言い回しや水増しは、書いている最中より読み直すときのほうが見つけやすいからです。
-   **書式。** 次の項目は見落としやすいので、1つずつ確かめます。

```text
- [ ] name が64文字以内で、小文字、数字、ハイフンだけを使っている
- [ ] name に anthropic と claude が入っていない
- [ ] description が1,024文字以内で、XML タグを含まない
- [ ] リンク先のファイルがすべて存在する
- [ ] 参照ファイルがすべて SKILL.md から直接リンクされている
- [ ] H1 が1つだけで、見出しが重複せず、階層を飛ばしていない
- [ ] コードブロックすべてに言語が書いてある
- [ ] 100行を超える参照ファイルに目次がある
```

最後に、全体を次の観点で読みます。

- H1 と導入を読んだだけで、初めての人がスキルの目的を理解できるか。
- 見出しだけを読んで、ファイルの構成が分かるか。
- どの段落にも、削ると困る情報があるか。
- 想定した依頼を受けたとき、description を読んだ Claude がこのスキルを選ぶか。

## 既存のスキルをレビューする場合

レビュー結果は、次の形で報告します。
指摘ごとに場所と修正案があれば、ユーザーは各指摘を受け入れるかをすぐ決められます。

```markdown
## レビュー結果: skill-name

### 修正が必要な点

-   `SKILL.md:3` の description が一人称で書かれています。
    "Processes ..." のように三人称に書き換えてください。

### 改善を勧める点

-   `references/api.md` は140行ありますが、目次がありません。
    冒頭に `## 目次` を追加してください。

### 良い点

-   ワークフローの各ステップに、結果を確かめる手順があります。
```

ユーザーに修正を頼まれた場合は、修正した後に Step 5 を実行します。

## 詳細資料

-   [Anthropic のベストプラクティス](references/anthropic-best-practices.md)
    には、自由度の決め方、ファイルの分け方、スクリプトの書き方、評価の作り方、
    公開前のチェックリストがあります。
    スキルの構成に迷ったときに読みます。
-   [マークダウンスタイル](references/markdown-style.md) には、書式の規則ごとの
    理由と良い例と悪い例、2つのガイドが食い違う箇所の扱いがあります。
    書式の規則の理由や例を確かめるときに読みます。
-   [文章の書き方](references/prose-style.md) には、文の組み立て方、
    AI 特有の言い回しと水増しの例と直し方、読み直しのチェックリストがあります。
    本文を書くときと、Step 5 で読み直すときに読みます。
-   [スキルのテンプレート](assets/skill-template.md) は、新しいスキルの出発点です。
